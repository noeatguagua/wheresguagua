# 前端設計：瓜瓜去哪儿（手機版介面）

**狀態：** v0.1（已實作原型，見 [app/m.html](../app/m.html)）
**依據：** 設計稿 `gb.pdf`（4 頁，1242×2208，即 414×736 邏輯像素的 3 倍圖）、背景 `gbbackground.pdf`
**對接：** 引擎 [app/engine.js](../app/engine.js)，輸出契約 [API-spec-v0.md](API-spec-v0.md)；架構決策 [ADR-001](ADR-001_捷運無礙行架構.md)
**日期：** 2026-11-08

---

## 1. 需求

**功能**
- 輸入起、迄站與「電梯／手扶梯」偏好，產生無障礙路線。
- 每一頁都是**單獨滿屏**；**只有白色按鈕能進到下一頁**。
- 站名底色 ＝ 該捷運線的顏色；**轉乘站為兩條線顏色的過渡漸層**。

**非功能**：手機優先（以 414×736 為基準，隨寬度等比縮放）、無建置步驟（沿用靜態頁）、離線可算（資料與引擎都在本機）、對輪椅使用者不隱瞞風險。

**限制**：嚴格遵守設計稿風格；不改引擎與輸出契約；舊版 [app/index.html](../app/index.html) 不動。

## 2. 畫面與流程

```
  [1 首頁] ──「路線生成」──▶ [2 總覽] ──「確定行程」──▶ [3 第 1 段] ──「下一步」──▶ … ──▶ [4 最後一段] ──「結束」──▶ [1 首頁]
   起/迄站、電梯/手扶梯          最佳路線 約 N 分              每段車程一頁                              最後一頁含出站與出口
```

| 頁 | 畫面 | 白色按鈕 | 內容（引擎來源） |
|---|---|---|---|
| 1 | 首頁 | 路線生成 | 起迄站輸入（欄位內輸入＋下拉建議）、上下樓偏好 |
| 2 | 總覽 | 確定行程 | `route.totalMin`、起訖站、時間軸（每段 `ride`／`transfer`／`exit`） |
| 3…n−1 | 步驟（中間段） | 下一步 | 該段車廂格、建議車廂、電梯說明 |
| n | 步驟（最後一段） | 結束 | 同上，加「轉乘」（若有）與「出站」＋ 出口編號 |

- 步驟頁數 ＝ 搭乘段數（`ride` 的數量）。有轉乘時，轉乘列顯示在**下一段**的頁首（對應設計稿第 4 頁）。
- 瀏覽器返回鍵可退回上一頁；按「結束」回首頁並清除路線。
- 鍵盤 Enter 只用來選站，**不會送出表單**（以符合「與白色按鈕交互後才進下一頁」）。

## 3. 設計 tokens

| 項目 | 值 |
|---|---|
| 背景 | `#000f9c`；光暈圖 [assets/bg.webp](../app/assets/bg.webp)（由 gbbackground.pdf 以「白色疊加＋透明度」還原，217 KB） |
| 外框 | 白色 1.5u 線、圓角 22u、距邊 18u，內容裁切於框內 |
| 字體 | Noto Serif TC 700／900（Google Fonts），後備 Songti TC、PMingLiU |
| 大標 | 57u，行高 76u；「儿」為 0.62 倍、500 字重 |
| 站名底色 | 圓角 8u、字 22u、白字；見 §4 |
| 白色按鈕 | 白底、藍字（`#000f9c`）、字距 0.5em、按下縮 3% |
| 動畫 | 換頁：淡入＋上移 14u（340 ms）；站名建議：高度／透明度展開（260 ms）；建議車廂：彈跳。`prefers-reduced-motion` 時全部關閉 |

`1u` ＝ 設計稿 414 寬時的 1 個邏輯像素，CSS 以 `--u = min(100vw, 480px) / 414` 等比縮放；桌機置中、最寬 480。

|---|---|---|---|

後三線設計稿沒有出現，是我依板南、文湖的色調推出，並確保大字白字對比 ≥ 3:1。**若有官方色票請提供，改 `m.css` 的五個 CSS 變數即可。**

## 4. 站名底色規則

- 單一路線的站：該線色。
- 轉乘站（**僅限本次行程真的要在該站換車**）：`linear-gradient(90deg, 線A, 線B)`，**左側為「先到的那條線」**。
  - 轉乘站在同一次行程中的每一處出現（上一段終點、轉乘列、下一段起點）都用同一個方向，與設計稿的「忠孝復興」一致（板南 → 文湖）。
  - 起、迄站、以及沒有在該站換車的任何站，一律用搭乘那條線的單色（例如台北車站→忠孝復興，兩站都是藍色）。
  - 下拉建議中的站名沒有方向，依線序排列。
- 實作：[m.js](../app/m.js) `bgOf(name, firstLine)`；資料來自 `E.stations()` 的 `lines[]`。

## 5. 引擎欄位 → 畫面

| 畫面元素 | 欄位 |
|---|---|
| 「約 N 分」 | `Math.round(route.totalMin)` |
| 起訖站與站碼 | `steps[0].station`、`steps[last].station`；站碼取 `E.stations()` 該站第一條線（設計稿的 B01、B06 為示意，改用真實站碼如 BL18） |
| 「A 往 B」 | `ride.from`、`ride.to`（設計稿的「往」後面是本段下車站） |
| 「往 X 方向月台」 | `ride.towards`（小字，補在設計稿沒有的資訊，與月台看板對得上） |
| 建議車廂、車廂格 | `ride.car.recommended`、`ride.car.total`（格數隨線，文湖 4、板南 6） |
| 「電梯 將在下車處附近」 | `ride.alight.targetCars` 含 `car.recommended` 時成立；否則見 §6 |
| 轉乘列 | `transfer.station`、`fromLine` |
| 出站、出口 | `exit.station`；`exit.elevatorExits[].id`，顯示為「出口1 , 出口3」 |
| 偏好 → `mode`（標題「選擇需求設施」） | 只勾電梯 ＝ `wheel`；勾手扶梯 ＝ `walk`；兩個都勾、**兩個都不勾** ＝ `walk`（電梯或手扶梯皆可，不設限）。注意：沒勾選時不會限制只走電梯，需要電梯的使用者要自己勾「電梯」 |

呼叫方式：`E.plan({from, to, mode, max: 1})`，出發時間預設為現在（臺北時間）。

## 6. 邊界情況與風險資訊（API-spec §7 的要求，用小字提示列，不改版型）

| 情況 | 呈現 |
|---|---|
| `searchMode: "relaxed"` 或 `warnings[]` 有 `NO_ELEVATOR_PLATFORM` | 總覽標題下方白框：「注意　此路線經過沒有電梯的月台：動物園（文湖線），請先向站務人員確認。」 |
| `flags.anomalyStations` 非空 | 總覽白框：「電梯異常公告　站名…」 |
| `car.basis: "mirrored"` | 該段下方小字「※ 車廂位置為推算，尚未現場核對」 |
| `car.recommended` 為 `null` | 「此段沒有車廂建議,請依站內指引搭乘」，車廂格不亮 |
| 下車站沒有標記資料（`alight.dataBasis` ≠ `annotated`） | 不宣稱「電梯將在下車處附近」，改為「下車站電梯位置請依站內指引」 |
| 電梯不在建議車廂 | 「電梯 在第 X 節車廂附近」 |
| 所有路線頁尾 | 「時間、車廂為預估，電梯以車站現場公告為準」 |
| 錯誤碼 | `SAME_STATION`「起站與迄站相同」、`NO_ROUTE`「找不到可行的路線」、站名無法辨識「找不到起站「…」，請從建議中選擇」 |

## 7. 無障礙與觸控

- 全部互動元件為原生 `button`／`input`／`label`；站名欄位為 `combobox`＋`listbox`（方向鍵、Enter、Esc）。
- 換頁後焦點移到該頁大標，並以 `aria-live` 播報「第 N 段，共 M 段」。
- 車廂格有 `aria-label`（「共 6 節車廂，建議搭第 3 節」）；裝飾圖示 `aria-hidden`。
- 觸控目標：站名欄位 68u、按鈕 55–67u、對調箭頭 52u，都 ≥ 44px；**「電梯」「手扶梯」勾選框只有 19u（依設計稿），點擊範圍僅比文字略大，低於 44px，是已知落差。**
- **已知落差：** 白字在 `#c98500`（中和新蘆線）上約 3:1，只達大字標準；已加細微文字陰影。

## 7.1 站名下拉選單（起站、迄站）

與車廂標記工具（[annotator](../annotator/index.html)）的「路線分類展示」同一套結構，外觀沿用主頁的白色圓角邊框。

```
┌──────────────────────────────┐   點欄位或開始輸入即展開（起站向下、迄站向上）
│ ( 全部 )( ●文湖 )( ●淡水信義 )  │   篩選鈕：全部＋五條線；選中者填白、藍字
│ ( ●松山新店 )( ●中和新蘆 )( ●板南 )│   （與車廂格的選中狀態一致）
├──────────────────────────────┤
│ ▌文湖線 ▌（線色底的標題列）      │   依線分組，順序：文湖、淡水信義、松山新店、中和新蘆、板南
│ BR01  動物園                   │   列：站碼＋站名，站碼由小到大
│ BR02  木柵                     │
│ ▌板南線 ▌                      │   轉乘站在各線底下各出現一次（與 annotator 相同）
└──────────────────────────────┘
```

| 項目 | 規則 |
|---|---|
| 搜尋 | 輸入文字時在目前篩選範圍內比對站名（臺／台通用）或站碼開頭；篩選鈕與輸入可同時使用 |
| 最近查詢 | 沒有輸入文字、篩選為「全部」時，最上方列出最近 4 個站（存在瀏覽器，失敗不影響） |
| 高度 | 最多 300u，且不超出外框；超出時列表內捲動，篩選鈕固定在頂端 |
| 選取 | 點列、方向鍵＋Enter、或 Enter 選第一筆；選定後起站自動跳到迄站，迄站選完收起鍵盤 |
| 動畫 | 高度／透明度／位移展開（260 ms）；`prefers-reduced-motion` 時關閉 |
| 資料 | `E.stations()` 的 `lines[]`（站碼、線名）；線色同 §3 |
| 無障礙 | `combobox`＋`listbox`，選項 `role=option`；篩選鈕是原生 `button`，不進入 Tab 順序（避免打斷輸入，可用滑鼠／觸控） |

**取捨：** 轉乘站重複出現（13 站各出現兩次）換來「依線瀏覽」的直覺，與標記工具一致；代價是列表較長（全部 126 列）；缺點由篩選鈕與搜尋補足。**待回頭檢視：** 篩選鈕目前只能觸控／滑鼠操作，鍵盤使用者只能靠輸入搜尋；若要補，可加 `←/→` 切換篩選。

## 7.2 安裝到桌面（PWA）

| 項目 | 做法 |
|---|---|
| 入口 | 使用瀏覽器選單的「安裝應用程式／加入主畫面」。頁面上**不再放安裝按鈕**（首頁右上角改為語言切換） |
| `manifest.webmanifest` | `display: standalone`、直式、背景與主題色 `#000f9c`、`start_url: ./m.html`（相對路徑，GitHub Pages 子路徑與本機都可用） |
| 圖示 | `assets/icons/`：192、512、maskable 512、apple-touch-icon 180；深藍底、光暈、白框與「瓜瓜」，由設計稿風格自行繪製 |
| iOS | `apple-mobile-web-app-capable`、`black-translucent` 狀態列（內容已用 safe-area 避開瀏覽器列） |
| 離線 | `sw.js`：同源 GET「網路優先、失敗用快取」，更新網站後立刻拿到新版；預快取外殼與資料。字體為跨來源，離線時退回系統宋體 |

**取捨：** 網路優先讓更新即時，但離線時只能用「上次成功載入過」的檔案。改了 `sw.js` 的預快取清單或策略時要把 `VERSION` 加一。

## 7.3 中英文介面

| 項目 | 規則 |
|---|---|
| 切換 | 首頁右上角圓形按鈕：中文介面顯示「EN」，英文介面顯示「中」。預設依 `navigator.language`（`zh*` ＝ 中文，其餘英文），選擇後存在瀏覽器；切換時目前畫面（含已產生的路線）立即重繪 |
| 文案 | `m.js` 的 `STR.zh`／`STR.en` 兩份字典；靜態文字用 `applyStatic()` 套用，動態文字用 `t(key, …)` |
| 站名譯名 | `stations_en.js`（109 站，取自 TDX `StationName.En`）。**下拉選單：** 中文介面＝中文在左、英文在右；英文介面＝英文在左、中文在右。**路線頁的站名方塊：** 站名在上，譯名在下，皆在底色（線色／轉乘漸層）方塊內 |
| 輸入 | 欄位可輸入中文（臺／台、有無「站」皆可）或英文站名（不分大小寫、可省略 Station）；搜尋也比對英文與站碼 |
| 英文版面 | 字較長，標題、內文、欄位字級縮小，白色按鈕取消字距；頁首「About N min」不折行 |

**待回頭檢視：** 英文文案（句型、「Platform toward …」）是我寫的，未經母語者或捷運官方用語校對；英文站名採 TDX 的官方譯名（例如「Taipei Main Station」），部分與路牌寫法可能略有差異。

## 7.4 到站時間（班表倒數）

步驟頁的圖二上方空間顯示「**到站時間** N 分　08:48 發車」（用班表算，畫面不標「班表」；沒有班表的線才標「預估」）（只顯示分鐘，無條件捨去；不到 1 分鐘顯示「即將進站」）。

| 項目 | 規則 |
|---|---|
| 資料 | `timetable.js`（TDX StationTimeTable，延遲載入、不含文湖線）；只有分鐘精度，秒數＝該分鐘 0 秒 |
| 取哪一班 | 以裝置現在時間為準：引擎算出「預計到月台」的時刻（`board.arrive`，相對按下「路線生成」的時間）之後的**第一班**發車；車開走後自動換下一班；末班後顯示「末班車已過」 |
| 方向 | 先用終點站名（`ride.towards`）對班表的終點，找不到再用下一站站碼比大小判斷；同方向的短返車一併計入 |
| 營運日 | 臺北時間 04:00 前算前一天；依週一至五／六／日挑班表，**國定假日不另處理** |
| 沒有班表 | 文湖線等沒有班表的情況，退回引擎預估（固定候車假設），標示「預估」 |
| 非即時 | 這是**時刻表**，不是列車即時位置；誤點、臨時停駛都不會反映（即時到站需捷運會員 API） |
| 轉乘後的段落 | 倒數的是「依目前進度，預計到月台後的第一班」，從使用者按下路線生成那刻起算，不代表換乘後才開始數 |

## 8. 決策紀錄

| # | 決策 | 理由／取捨 |
|---|---|---|
| F1 | 交付：設計文件＋新檔 `app/m.html`，舊版 `index.html` 不動 | 使用者指定「文件＋直接實作」；專案非 git 倉庫，不覆蓋舊版 |

## 9. 未決與待回頭檢視

1. **嬰兒車模式**：設計稿的「電梯／手扶梯」無法區分輪椅與嬰兒車，兩者目前都走 `wheel`。若需要，加第三個選項。
2. **出發時間**：設計稿沒有，固定為現在；之後可在總覽頁加「出發時間」。
3. **後三線色票**（§3）與設計稿以外的狀態（錯誤、警示）需設計師確認。
4. **字體**：目前依賴 Google Fonts 連線；離線或被擋時退回系統宋體。若要完全離線，需把 Noto Serif TC 子集放進 `assets/`。
5. **鍵盤彈出**：已用 `interactive-widget=resizes-content`，畫面被擠壓時首頁可捲動；實機（iOS Safari、Android Chrome）尚未驗證。
6. **未驗證項目**：只在桌面瀏覽器的手機尺寸模擬（414×736、390×844、360×600）驗證；沒有螢幕報讀器或實機測試。
7. 舊版 `index.html` 的功能（出發時間、替代路線、人流與電梯異常明細）在新介面尚未出現。
